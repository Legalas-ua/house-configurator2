# РОЗДІЛ 2. Які елементи є на сайті

> **Головне рішення продукту:** будинок збирається з **кімнат-модулів**.
> Кімната — найменша одиниця, якою оперує клієнт. Усе інше (контур, стіни,
> перекриття, дах) **виводиться** з набору кімнат, а не малюється окремо.
> Див. рішення 6 у розділі 3.1.

Повний перелік. Для кожного: **параметри** (що можна змінити), **варіанти**,
**правила** (як будується і з чим стикується).

## 2.1. Ділянка й оточення

### Земля
- Параметри: розмір ділянки (зараз фіксований квадрат).
- Правила: нуль сцени = верх фундаменту; земля опущена на висоту цоколя.

### Тераса
- Параметри: зони (прямокутники) на рівні землі або на перекритті.
- Варіанти: відкрита · під дахом (продовження звісу) · з парканом.
- Правила: зона тераси прив'язана до сітки; не перетинає будинок; настил
  ріжеться контуром зони.

### Паркан тераси
- Параметри: висота, крок стійок, тип заповнення (скло · рейки · суцільний).
- Правила: стоїть **на** настилі, а не в ньому; на розі стійка одна, спільна.

## 2.2. Коробка будинку

### Фундамент і цоколь
- Параметри: висота цоколя, матеріал.
- Правила: повторює контур поверху; верх = нуль будинку.

### Стіна зовнішня
- Параметри: товщина (єдина константа на весь проєкт), висота поверху.
- Правила: будується як смуга по контуру поверху; отвори ріже **один**
  механізм. ⚠️ У v2 їх було два, і другий роками закривав отвори вікон.

### Перегородка внутрішня
- Параметри: товщина.
- Правила: перегородка = **рівно перекриття з сусідньою кімнатою**, по кожному
  сусідові окремо. ⚠️ Смуга «на всю сторону кімнати» лягала в зовнішню стіну.

### Перекриття
- Параметри: товщина плити.
- Правила: контур поверху, витягнутий на товщину; верх = нуль наступного поверху.

### Сходи
- ⬜ **Рішення 4:** чи потрібні сходи у v3 (у v2 їх немає, для 2 поверхів це
  помітно).

## 2.3. Отвори

### Вікно
- Параметри: стіна, позиція вздовж стіни, ширина, висота, висота низу,
  кількість імпостів.
- Варіанти: звичайне · панорамне (в підлогу) · вузьке.
- Правила: не накладається на сусіднє вікно на тій самій стіні; не виходить за
  межі своєї стіни; рама сідає в отвір із зазором.

### Двері вхідні (у склопакеті)
- Параметри: секція у вікні, ширина полотна, фрамуга.
- Правила: низ на рівні підлоги; не нижче за вікно в тому ж отворі.

### Двері міжкімнатні й арки
- Параметри: перегородка, позиція, ширина, висота; тип (двері · арка · прохід).
- Правила: стоять лише в перегородці; не перетинають кут.

## 2.4. Дах — форма

### Зона даху
Дах складається із **зон**. Кожна зона — свій тип, кут і звіс.
- Параметри: контур (один або кілька прямокутників), тип, кут нахилу, звіс,
  напрям (поворот), «головна на стику».
- Варіанти типу: **плоский · двосхилий · односхилий · вальмовий**.

### Схил
- Правила: висота в точці = відстань до найближчого карниза × тангенс кута.
- Полігон схилу = площина, обмежена сусідніми схилами й контуром зони.

### Коник (гребінь)
- Лінія, де сходяться два схили однієї зони.

### Ребро вальми
- Діагональ від рогу до коника; бісектриса кута.

### Єндова
- Лінія, де сходяться два схили, обидва спрямовані **в неї**.
- ⚠️ Єндова між двома ЗОНАМИ мусить бути порахована **один раз** і бути
  спільною. У v2 кожна зона рахувала свою — виходило дві планки на одному місці.

### Врізка двох зон (найважче місце)
- Правило: у кожній точці лишається **верхня площина**, нижня зрізається.
- На самій лінії перетину виграє «головний» на стику: вищий коник → галочка →
  стабільний порядок.
- ⚠️ Різати треба по **видимих** площинах, а не по розрахункових: різниця в
  товщину плити дає провалля по всьому контуру врізки.
- ⚠️ Сусідом вважається кожен, чиї схили **накладаються**, а не лише той, з ким
  спільна грань. Дві зони хрестом спільної грані не мають.

### Фронтон
- Стіна під схилом (там, де дах не звисає карнизом).
- ⚠️ Під підрізаною ділянкою фронтон іде до **чужого** схилу, а не до свого.

### Парапет (для плоского)
- Параметри: висота, товщина.
- Правила: по всьому контуру зони; на розі — одна деталь, не дві.

### Звіс
- Параметри: 0 або від 300 мм (проміжних не буває — на фасаді не читаються).
- Правила: звіс міняє те, ЧИМ є тіло даху: без звісу це продовження стіни (і
  зверху лежить плита покрівлі), зі звісом — сам дах.

## 2.5. Кожухи й планки

Це окремий клас елементів. **Один механізм: профіль, протягнутий по лінії.**

| Кожух | Де йде | Профіль |
|---|---|---|
| **Карнизний** | по нижньому краю схилу | від нижнього ребра торця до краю матеріалу, стик під 90° |
| **Торцевий** | по фронтону, знизу вгору | повторює площину схилу + полиця поверх матеріалу |
| **Гребеневий** | по конику | накривка через шов |
| **Вальмовий** | по діагональному ребру | те саме, під кутом |
| **Єндовий** | по лінії єндови | ширший, лягає в складку |
| **Парапетний** | по верху парапету | П-подібний, зі звисом на обидва боки |
| **Капельник** | по краю карниза | продовжує кожух униз |
| **Верх односхилого** | де дах упирається в стіну | полиця + відворот угору по стіні |

**Правила, спільні для всіх кожухів:**
1. Кожух стоїть **вище за найвищу точку рельєфу** матеріалу (черепиця
   задирається рядами — двох міліметрів не вистачає).
2. Підйом відкладається **по нормалі** до схилу, не по вертикалі.
3. Два сусідні кожухи або стикуються митрою (45°/135°), або один володіє
   кутом — але **ніколи не перетинаються і не лишають щілини**.
4. Торцевий кожух закриває фронтон **по всій довжині**, зокрема під сусіднім
   дахом.
5. Геометрія карнизного вузла виводиться, а не підбирається:
   за висоти торця `H` і кута `α` — **звіс матеріалу = H·sin α**, **довжина
   кожуха = H·cos α**.

## 2.6. Матеріали

| Поверхня | Варіанти | Параметри |
|---|---|---|
| **Стіни** | клінкер · штукатурка · термодерево · панелі | розмір елемента, шов, напрям, колір |
| **Дах** | натуральна черепиця · металочерепиця · фальц · ґонт · профнастил · рулон (плоский) | колір, колір планок |
| **Тераса** | дошка · керамограніт · камінь | ширина/формат, зазор |
| **Підлога** | дошка · плитка · камінь · килим | формат, напрям |
| **Паркан** | ⬜ вирішити | — |

**Правила розкладки:**
- Матеріал ріжеться **полігоном** поверхні. ⚠️ Елемент, що перетинає межу,
  ріжеться — а не зникає цілком (у v2 зникав, і по врізці лишалась рвана кайма).
- Рельєф (фальці, гофра) має **ту саму довжину**, що й лист — до краю звісу.
- Ріг стіни: володіє горизонтальна грань, вертикальна відступає до її
  зовнішньої площини.

## 2.7. Службові елементи

- **Підсвітка** вибраного/наведеного.
- **Ручки** редагування (тягнути край, кут).
- **Розміри** — підписи в метрах на вибраному елементі.
- **Помилки** — червона підсвітка + пояснення в панелі.
- **Сітка прив'язки** — під планом, у ручному режимі.

# РОЗДІЛ 3. Як воно все з'являється

## 3.1. Кроки майстра

Зараз у v2 одинадцять: бюджет · форма · кімнати · вікна · зони даху · дах ·
фасад · матеріал даху · тераса · матеріал тераси · інтер'єр.

⬜ **Рішення 5: набір кроків.** Варіанти:

| Варіант | Кроків | Ідея |
|---|---|---|
| Як зараз | 11 | Кожен матеріал — окремий крок |
| Згорнутий | 6-7 | Форма → Планування → Отвори → Дах → Матеріали (усі разом) → Тераса → Заявка |
| Вільний | — | Без майстра: панель із розділами, клієнт ходить як хоче |

✅ **Рішення 6 (ухвалено): свобода на рівні КІМНАТ-МОДУЛІВ.**

Планування не малюється, а **збирається з кімнат**. Кімната — це модуль:
у неї є тип, межі розмірів і правила сусідства. Клієнт додає «ще одну
спальню» чи «кабінет» — будинок росте.

Що це дає:
- план **завжди валідний** — не буває кімнати без стіни чи дірки в контурі;
- контур будинку **виводиться** зі складених кімнат;
- **дах рахується з контуру автоматично** — зникають довільні зони під
  довільними кутами, а з ними й більшість того, що ми тижнями лагодили у v2;
- ціна чесна: у кожної кімнати своя площа й вартість.

Чого НЕ буде: малювання стін з нуля, довільні зони даху, довільні контури.
Замість цього — кнопка «хочу індивідуальний проєкт» → заявка. Такий клієнт
усе одно йде до архітектора.

Три рівні свободи в одному потоці:

| Рівень | Що дозволено | Для кого |
|---|---|---|
| Вибір | Планування з каталогу, поверховість | ~80% — будинок за 5 хвилин |
| Підгонка | Додати/прибрати кімнату, змінити її розмір у межах, вікна, тип даху, матеріали | ~15% |
| Індивідуальне | — (заявка на проєкт) | ~5% |

## 3.2. Що видно в 3D на кожному кроці

Правило: **на своєму кроці елемент уже видимий**, із типовим значенням.
⚠️ Чекати першого кліку не можна: картка в панелі підсвічена, а будинок
базовий — це читається як несправність.

| Крок | Що з'являється в 3D |
|---|---|
| Бюджет | Нічого (3D сховано) |
| Форма | Плита фундаменту, контур |
| Кімнати | Кольорові зони на плиті, вид зверху |
| Вікна | Коробка будинку піднімається, з'являються отвори |
| Дах | Дах виростає зверху вниз |
| Матеріали | Поверхні перефарбовуються/обростають рельєфом |
| Тераса | Настил і паркан |
| Інтер'єр | Відсікання даху, видно підлоги й двері |

## 3.3. Правила анімації

Вивірені на v2, переносимо як принцип:

1. **Нічого не «перескакує».** Позицією й масштабом володіє лише кадрова
   анімація. ⚠️ Не прив'язувати змінні значення до реактивних пропсів —
   перебиває анімацію й дає стрибок.
2. **Стабільна ідентичність.** Кожен елемент має id за **роллю**
   (`bedroom-2`), а не за номером. Прибраний елемент зникає плавно, а не
   «морфить» у сусіда.
3. **Секвенція, процеси не перетинаються:**
   - додавання: спершу росте основа, потім чекає паузу і росте новий елемент;
   - видалення: спершу зникає елемент, потім стискається основа.
4. **Напрямок росту осмислений:** стіни — знизу вгору, дах — зверху вниз,
   матеріал — від карниза до коника.

⬜ **Рішення 7:** швидкість анімацій — зараз ~0.35 с. Лишаємо / швидше / вимикач
для тих, хто клікає швидко.

## 3.5. Каскадне скидання

Коли клієнт вертається назад і міняє основу — що обнуляється:

| Зміна | Що скидається |

| Форма будинку | Планування, вікна, дах, тераса — усе |
| Кількість поверхів | Дах, вікна другого поверху |
| Планування | Вікна, внутрішні двері, підлоги |
| Зони даху | Матеріал даху лишається, форма перераховується |

⬜ **Рішення 8:** попереджати діалогом («це скине дах — продовжити?») чи
скидати мовчки?

# РОЗДІЛ 4. Як воно все оформлене

## 4.1. Логіка оздоблення

Оздоблення = **поверхня + матеріал + параметри**. Три рівні вибору:

1. **На весь будинок** — один матеріал стін, один покрівлі (швидкий шлях).
2. **На поверх** — різні матеріали першого й другого.
3. **На окрему грань/зону** — ручний режим.

⬜ **Рішення 9:** чи потрібні всі три рівні, чи досить перших двох.

## 4.2. Правила стикування матеріалів

| Стик | Правило |
|---|---|
| Ріг стіни | Володіє горизонтальна грань; вертикальна відступає до зовнішньої площини сусіда |
| Стіна ↔ дах | Стіна доходить до **видимої** площини даху |
| Стіна ↔ цоколь | Цоколь виступає на свою товщину |
| Дах ↔ дах (єндова) | Спільна лінія, один кожух |
| Матеріал ↔ кожух | Кожух завжди вище за рельєф матеріалу |
| Тераса ↔ стіна | Настил підходить упритул, зазор під дилатацію |

## 4.3. Пресети

⬜ **Рішення 10:** чи робимо готові комплекти («Скандинавський», «Мінімалізм»,
«Класика») — один клік і всі матеріали підібрані. Це сильно скорочує шлях
клієнта, але потребує дизайнерських рішень від тебе.

## 4.4. Ціна й заявка

- Ціна рахується з площ і матеріалів, показується орієнтовно.
- Джерело цін — зовнішнє, підключається окремо.
- Заявка: ім'я, телефон, пошта + збережена конфігурація.
- Токени й доступи — тільки на боці сервера, ніколи у фронтенді.

⬜ **Рішення 11:** показувати ціну весь час чи лише на підсумку?

# РОЗДІЛ 5. Технічні правила (коротко)

Детально — у розділах вище; тут те, що стосується коду.

## 5.1. Три уроки з v2

1. **Геометрія рахувалась вибіркою** (проби + уточнення). Усі щілини, шви й
   дірки — звідси. У v3 поверхня — **полігон**, отриманий перетином площин.
2. **Кожухи були коробками** — тому неможлива митра й гнутий профіль. У v3 —
   **протяжка профілю по лінії**.
3. **Числова перевірка з'явилась пізно.** Її перший запуск знайшов 52% площі
   під двома дахами. У v3 — з першого комміту.

## 5.2. Ядро: три примітиви

1. **Полігон** — контур + отвори; перетин, різниця, зсув, тріангуляція.
2. **Тіло** — полігон на товщину або обмежений площинами.
3. **Профіль по лінії** — переріз + шлях + правило кута.

Дах, стіна, кожух, настил, паркан — комбінації цих трьох.

## 5.3. Порядок папок

`config` = тільки дані · `lib` = чисті функції (без React і Three) ·
`scene` = все всередині Canvas · `components` = DOM · `locales` = всі тексти.
✅ Це з v2 працювало бездоганно.

## 5.4. Дисципліна

- Одна константа — одне джерело. ⚠️ Кожна копія рано чи пізно розходиться.
- Перевірка після кожної правки геометрії.
- Карта `docs/MAP.md` (етап → елемент → файл:рядки) оновлюється разом із кодом.
