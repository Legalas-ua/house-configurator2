# Методичка нового конфігуратора (v3)

Робочий документ. Пишемо ДО коду: спершу домовляємось, як будується кожен
елемент, і лише потім програмуємо. v2 (`D:\house-configurator2`) лишається
живим прикладом — його можна відкривати поруч і порівнювати.

Статус: **чернетка**. Розділи, позначені «⬜ вирішити», чекають на рішення Lev.

---

## 1. Три уроки з v2

Не про дизайн і не про структуру папок — про фундамент. Саме вони з'їли
більшість часу.

### 1.1. Геометрія рахувалась ВИБІРКОЮ, а не точно

Схил даху шукався пробами: 96 проб уздовж карниза × кожні 5 см углиб, краї
уточнювались поділом навпіл. Кожна щілина, шов і дірка, які ми ловили, — це
«проба не влучила» або «уточнення пішло не в той бік». Їх було багато:
недоріз по коньку, рядок дірок уздовж врізки, шов між клаптями, зникла
смужка біля рогу.

**Правило v3: жодної вибірки в геометрії.** Поверхня — це ПОЛІГОН, отриманий
перетином площин і півплощин. Тоді «дірка» неможлива як клас помилки.

### 1.2. Кожухи — коробки в InstancedMesh

Через це неможливі: митра 45°, гнута пластина, П-подібний капельник. Кожен
вузол доводилось імітувати двома-трьома коробками, і кути ніколи не сходились.

**Правило v3: кожух = ПРОТЯЖКА ПРОФІЛЮ по ламаній** (profile sweep). Один
механізм дає гребінь, торець, єндову, карниз, капельник і парапет — з
правильними митрами на кутах.

### 1.3. Числова перевірка з'явилась пізно

Її перший запуск за п'ять хвилин знайшов **52% площі під двома дахами** —
баг, який жив місяцями й був невидимий на око.

**Правило v3: перевірка в першому комміті, а не в сотому.** Спершу метрика,
потім елемент.

### Що з v2 працювало добре (лишаємо як принцип)

- **Розподіл папок:** `config` = тільки дані · `lib` = чисті функції без React
  і Three · `scene` = все всередині Canvas · `components` = DOM · `locales` =
  всі тексти. Жодного разу не пошкодували.
- **Одна константа — одне джерело.** Кожна копія (`ROOF_T` жив у трьох місцях)
  рано чи пізно розходилась і давала артефакт.
- **Кроки майстра — це дані.** Новий крок = запис у `steps.ts` + тексти.
- **Карта `docs/MAP.md`** (етап → елемент → файл:рядки) і пам'ять із граблями.

## 2. Технічний фундамент v3

| Рішення | Чому |
|---|---|
| React 19.1 · TS · Vite 7 · react-three-fiber · zustand | Це працює. React 19.2 / Vite 8 ламали R3F — версії тримаємо закріпленими |
| **Полігональне ядро** | Кожна поверхня — плоский полігон; операції: перетин із півплощиною, різниця, об'єднання. Ніяких проб |
| **Протяжка профілю** | Кожух, планка, капельник, парапет — усе це профіль, протягнутий по ламаній, із митрою на зламах |
| **Розкладка по полігону** | Матеріал ріжеться полігоном схилу, а не «смугою»: обрізок завжди рівний |
| **Перевірка з першого дня** | `npm run check` + випадковий перебір конфігурацій |
| Одиниці | метри, права система координат, Y — вгору (як у v2) |

### Ядро: три примітиви, з яких будується все

1. **Полігон у площині** — контур + отвори. Уміє: перетин, різницю, зсув
   (offset), тріангуляцію.
2. **Тіло** — полігон, витягнутий на товщину, або обмежений набором площин.
3. **Профіль по ламаній** — переріз (2D-профіль) + шлях + правило кута
   (митра / стик / внахлест).

Дах, стіна, кожух, настил тераси, паркан — усе це комбінації цих трьох.

## 3. Як будується кожен елемент

Для кожного елемента фіксуємо ЧОТИРИ речі: з чого будується · чим ріжеться ·
як стикується із сусідом · чим перевіряється.

### 3.1. Стіна

- **Будується:** контур поверху (об'єднання прямокутників) → смуга завтовшки
  `WALL_T` → тіло.
- **Ріжеться:** отворами вікон і дверей. **ОДИН механізм різання отворів.**
  У v2 їх було два, і другий роками закривав отвори — не повторювати.
- **Стик:** ріг належить горизонтальній грані, вертикальна відступає рівно до
  її зовнішньої площини (і в стіні, і в оздобленні).
- **Перевірка:** кожен отвір наскрізний; товщина однакова; ріг без щілини й без
  подвійного матеріалу.

### 3.2. Перекриття і цоколь

- **Будується:** той самий контур, витягнутий на товщину плити.
- **Стик:** верх плити = нуль наступного поверху.
- **Перевірка:** плита не виступає за стіну, під дахом немає порожнечі.

### 3.3. Вікно і двері

- **Будується:** специфікація (позиція вздовж стіни, ширина, висота, низ) →
  коробка + скло + імпости. Двері — те саме плюс фрамуга й полотно.
- **Ріжеться:** нічим; сама ріже стіну.
- **Стик:** рама сідає в отвір із зазором; відкоси беруть товщину стіни.
- **Перевірка:** вікна на одній стіні не накладаються; отвір існує; вікно не
  нижче за двері в тому ж отворі.

### 3.4. Дах — форма

Чотири типи, як у v2: **плоский · двосхилий · односхилий · вальмовий**.

- **Будується:** контур зони → площини схилів → полігон кожного схилу як
  перетин площини з півплощинами сусідніх схилів.
- **Врізка (правило Lev):** у кожній точці лишається ВЕРХНЯ площина, нижня
  зрізається. На самій лінії перетину виграє головний на стику (вищий коник →
  галочка → стабільний порядок). Ріжуть саме ЗОВНІШНІ (видимі) площини, а не
  розрахункові: різниця в товщину плити дає провалля.
- **Стик:** лінія перетину двох площин — це єндова; вона мусить бути СПІЛЬНОЮ
  для обох частин, порахованою один раз.
- **Перевірка:** нуль непокритої площі, нуль подвійного покриття, нуль
  вертикальних розривів на лінії врізки.

### 3.5. Дах — кожухи (правила Lev, з розрізів)

Один механізм — протяжка профілю. Різні місця дають різний профіль і різний шлях.

| Місце | Профіль | Шлях | Кут |
|---|---|---|---|
| **Карниз (звіс)** | від нижнього ребра торця до краю матеріалу, стик із матеріалом під **90°** | по карнизу | митра з торцевим |
| **Торець (фронтон)** | повторює площину схилу + полиця поверх матеріалу | по фронтону, від карниза до гребеня | знизу митра з карнизним, зверху стик із гребеневим («Г», не «Х») |
| **Гребінь** | накривка через коник | по коньку, до краю матеріалу | митра з торцевим |
| **Вальма** | те саме, що гребінь, тільки по діагоналі | по ребру вальми | митра з гребеневим |
| **Єндова** | ширша, лягає в складку | по лінії перетину, ОДНА на обидві частини | до карниза |
| **Парапет (плоский)** | П-подібна накривка зі звисом на обидва боки (капельники) | по контуру парапету | митра на кожному розі |
| **Верх односхилого** | полиця по схилу + відворот угору по стіні | по верхньому краю | — |

**Геометрія карнизного вузла (виведена, не підібрана).** За висоти торця `H`
і кута схилу `α`:

```
звіс матеріалу вздовж площини = H · sin α
довжина кожуха по нормалі     = H · cos α
```

Крутіший дах сам собою дає довший звіс і коротший кожух.

**Незмінні вимоги до всіх кожухів:**
- кожух стоїть ВИЩЕ за найвищу точку рельєфу матеріалу (черепиця задирається
  рядами — 2 мм не вистачає);
- підйом відкладається по НОРМАЛІ до схилу, не по вертикалі;
- сусідні кожухи або стикуються митрою, або один володіє кутом — але ніколи не
  перетинаються і не лишають щілини;
- кожух закриває торець фронтону ПО ВСІЙ довжині, включно з ділянкою під
  сусіднім дахом.

### 3.6. Матеріали даху

- **Будується:** розкладка елементів (черепиця, фальц, профнастил, ґонт) по
  площині схилу.
- **Ріжеться:** полігоном схилу. **Елемент, що перетинає межу, ріжеться, а не
  зникає** — у v2 він зникав цілком, і по врізці лишалась рвана кайма.
- **Стик:** рельєф (фальці, гофра) має ту саму довжину, що й лист, — до самого
  краю звісу.
- **Перевірка:** нуль елементів у повітрі; обрізок по краю рівний.

### 3.7. Матеріал стін (фасад)

- **Будується:** розкладка по грані стіни; грань — одиниця вибору.
- **Стик:** ріг належить горизонтальній грані; підкладка спиняється раніше за
  елементи.
- ⬜ **вирішити:** чи лишаємо об'ємну розкладку (InstancedMesh), чи переходимо
  на текстуру з нормалями. Об'ємна красивіша зблизька й дорожча.

### 3.8. Тераса, паркан, інтер'єр

- Тераса: зони на землі → настил (та сама розкладка по полігону).
- Паркан: профіль по контуру тераси, стоїть НА настилі.
- Інтер'єр: підлоги по кімнатах, перегородки, двері й арки.

## 4. Що беремо з v2 — по кожному пункту окремо

Головне побоювання Lev: перенести логіку елемента, а потім виявити, що саме
вона й псує. Тому правило просте: **переносимо лише те, що не суперечить
розділу 2** (полігони, протяжка, перевірка). Усе, що збудоване на вибірці —
переписуємо.

| З v2 | Рішення | Чому |
|---|---|---|
| Правила й граблі (пам'ять, ця методичка) | **БЕРЕМО** | Це головна цінність. Код можна написати вдруге, знання — ні |
| Числова перевірка (`checks/roof.check.ts`) | **БЕРЕМО**, адаптуємо | Метрики лишаються ті самі: діра · дубль · виліт · чужий · повітря · шов · ступ |
| Випадковий перебір конфігурацій | **БЕРЕМО** | Саме він знайшов те, чого не бачили сценарії |
| Каталог планувань (ASCII-сітки, Г-форма) | **БЕРЕМО** як дані | Це чисті дані, вони не залежать від геометрії |
| Списки матеріалів і їхні розміри | **БЕРЕМО** як дані | Взяті з реальних виробів |
| Тексти інтерфейсу (`locales/uk.ts`) | **БЕРЕМО** частково | Що не зміниться з дизайном |
| `lib/outline.ts` (об'єднання прямокутників у кільця) | ⬜ вирішити | Чиста функція, але в v3 має повертати ПОЛІГОН, а не кільця в старому форматі |
| `lib/roofSkeleton.ts` (прямий скелет) | **ПЕРЕПИСУЄМО** | Ідея правильна (висота = відстань до карниза), реалізація — вибіркова |
| `lib/roofSkin.ts` (покриття + кожухи) | **ПЕРЕПИСУЄМО** | Кожухи стануть протяжкою профілю |
| `scene/HouseShell.tsx` (2255 рядків) | **ПЕРЕПИСУЄМО** | Розпадеться на елементи згідно з розділом 3 |
| `lib/windows.ts`, `innerWalls.ts`, `cladding.ts` | ⬜ вирішити | Логіка здорова, але ріже й розкладає по-старому |
| Анімації плану (`PlanView`) | **БЕРЕМО** правила, код переписуємо | Правила вивірені з тобою: спершу плита, кімната чекає, зникнення швидке |
| Стор (`zustand`) і структура кроків | **БЕРЕМО** структуру | Вона себе виправдала |

⬜ **Головне рішення до обговорення:** чи лишаємо той самий набір кроків
майстра (11 штук), чи міняємо потік разом із дизайном.

## 5. Порядок робіт

1. **Методичка** (цей документ) — доти, доки в ній не лишиться жодного ⬜.
2. **Ядро геометрії без UI**: полігон, тіло, протяжка профілю + перевірка на
   них. Дивимось не на екран, а на числа.
3. **Дах на новому ядрі**: чотири типи, врізка, кожухи. Це найважча частина —
   робимо її ДРУГОЮ, поки нічого не заважає.
4. **Коробка будинку**: стіни, отвори, перекриття.
5. **Матеріали**: покрівля, фасад, тераса, підлоги.
6. **Дизайн і кроки майстра**: панель, потік, тексти.
7. **Заявка й ціна** — те, заради чого все існує.

Дизайн навмисно НЕ перший: він швидкий і безпечний, а геометрія — повільна й
чутлива. Але макет варто мати перед очима вже на кроці 2, щоб ядро не
суперечило задуму.
