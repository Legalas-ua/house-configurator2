# Дизайн-концепції нового конфігуратора

Дві повні концепції: типографіка, колір, композиція, рух. Обидві покривають
**усі кроки** майстра. Поле 3D навмисно порожнє — там буде сцена.

## Як подивитись

Відкрий у браузері подвійним кліком:

- `design/variant-a.html` — **Ательє** (світлий, редакційний)
- `design/variant-b.html` — **Студія** (темний, інструментальний)

Клікається все: кроки, картки, чипси, зразки матеріалів, повзунки. Спробуй
звузити вікно до ширини телефона — обидва перебудовуються.

## На що спирались

Не на смак, а на дані й правила:

| Джерело | Що взяли |
|---|---|
| Патерн **Interactive 3D Configurator** | Сцена — головний герой; UI мінімальним шаром поверх; ціна завжди на видноті; CTA у самому конфігураторі + липка нижня смуга |
| Палітра **Construction / Architecture** | Індустріальний сірий + будівельний помаранчевий (акцент виправлений під контраст 3:1) |
| Палітра **Architecture / Interior** | Майже чорний `#171717` + нейтральні — база для світлого варіанта |
| Пари шрифтів | «Editorial» (Playfair Display + Inter) і «Developer Mono» (JetBrains Mono + Inter) |
| Правила руху | 150–300 мс на мікровзаємодії, вихід коротший за вхід, `ease-out` на вхід, каскад 30–50 мс |
| Доступність | Контраст 4.5:1 для тексту, зона натискання ≥44 px, `prefers-reduced-motion`, фокус видимий |

**Чого свідомо уникали** (це антипатерни для такого продукту): фіолетово-рожеві
градієнти «як у AI-стартапу», 2D-плоскі композиції без сцени, декоративна
анімація без сенсу, емодзі замість іконок.

## Спільне для обох варіантів

### Реорганізація кроків: було 11 → стало 10

Матеріал переїхав до свого елемента, а не живе окремим кроком:

| Було (v2) | Стало |
|---|---|
| зони даху · дах | **Дах — форма** (тип, кут, звіс — в одному місці) |
| тераса · матеріал тераси | **Тераса** (зони + покриття + паркан) |
| — | **Підсумок** (конфігурація + заявка) |

Логіка проста: клієнт думає «дах», а не «спершу зони, потім тип». Кроків стало
менше, а останній нарешті веде до заявки — того, заради чого сайт існує.

### Правила, однакові в обох

- **Один головний CTA** на екрані. «Далі» — заповнений, «Назад» — контурний.
- **Ціна завжди на видноті**, з приміткою «орієнтовно».
- **Стани**: наведення · вибрано · помилка · недоступно — розрізняються не лише
  кольором (є рамка, крапка, вага шрифту).
- **Числа моноширинні** (табулярні) — ціна не «стрибає» при зміні.
- **Мобільний**: сцена зверху, панель знизу, кроки — горизонтальна стрічка.
- `prefers-reduced-motion` вимикає всю анімацію.

## ВАРІАНТ A — «Ательє»

> Світлий, редакційний. Багато повітря, тонкі лінії, великі числа.
> Відчуття: **архітектурне бюро**, а не інтернет-магазин.

### Композиція

```
┌────┬──────────────────────────────┬────────────┐
│ 76 │  Заголовок кроку + №         │  Панель    │
│ px │  ┌────────────────────────┐  │  400 px    │
│ ст │  │                        │  │            │
│ еп │  │      3D сцена          │  │  контроли  │
│ ер │  │      (рамка + сітка)   │  │            │
│    │  └────────────────────────┘  │  ─────────  │
│    │   інструменти сцени          │  ціна+CTA  │
└────┴──────────────────────────────┴────────────┘
```

Вертикальний степер лівою рейкою — не займає ширину. Сцена в рамці з полями
(як ілюстрація в журналі). Панель відділена лінією, без тіней.

### Типографіка

| Роль | Шрифт | Розмір / вага |
|---|---|---|
| Заголовок кроку | **Playfair Display** 500 | 34 px |
| Номер кроку (водяний) | Playfair Display 500 | 96 px, колір лінії |
| Ціна | Playfair Display 500 | 28 px, табулярні |
| Інтерфейс, картки | **Inter** 400/500 | 15 px |
| Мікрозаголовки | Inter 400 | 11 px, `letter-spacing .14em`, ВЕРХНІЙ РЕГІСТР |

Контраст двох шрифтів і робить «редакційність»: серіф лише в трьох місцях —
заголовок, велике число, ціна. Решта — нейтральний Inter.

### Палітра

| Роль | Hex | Де |
|---|---|---|
| Тло | `#FAFAF8` | сторінка (тепла крейда, не білий) |
| Поверхня | `#FFFFFF` | панель, картки |
| Текст | `#16130F` | заголовки, значення |
| Текст другорядний | `#6F6862` | підписи, пояснення |
| Лінії | `#E6E1DA` | рамки, розділювачі |
| **Акцент** | `#C4552D` | вибране, ліва риска на картці |
| Акцент-заливка | `#F6EBE5` | тло вибраної картки |
| Заглушка сцени | `#EDE7DE` | поле 3D |

Теракота — з твоїх референсів v2. Вона тут єдиний кольоровий елемент, тому
працює як указівник: «ось що вибрано».

### Рух

| Що | Тривалість | Крива |
|---|---|---|
| Наведення на картку | 220 мс | `cubic-bezier(.22,1,.36,1)` |
| Підйом картки | −1 px | там само |
| Зміна кроку (панель) | 320 мс, зсув 10 px угору + прозорість | ease-out |
| Каскад блоків | 40 мс між блоками | — |
| Натискання кнопки | 150 мс, масштаб 0.985 | — |

### Кому підходить

Преміальний сегмент, індивідуальні проєкти, клієнт «дивиться очима». Добре
виглядає у презентації й на друкованих матеріалах.

### Ризики

Світле тло «з'їдає» світлий будинок — сцені потрібен помітний контур або
контрастніша земля. Серіф на кирилиці треба перевірити на реальних текстах.

## ВАРІАНТ B — «Студія»

> Темний, інструментальний. Сцена на весь екран, панель — скляна картка поверх.
> Усі числа моноширинні. Відчуття: **робочий інструмент**, у якому будинок —
> єдиний герой.

### Композиція

```
┌───────────────────────────────────────────────┐
│ ДІМ.  кроки стрічкою ──────────►   184 м²     │
│                                               │
│            3D сцена на весь екран  ┌─────────┐│
│                                    │ панель  ││
│  ┌──┐                              │ скляна  ││
│  │ВЗ│ інструменти                  │ 352 px  ││
│  └──┘                              └─────────┘│
│ [Назад][Далі] ▬▬▬▬▬▬░░░░       3 240 000 ₴   │
└───────────────────────────────────────────────┘
```

Сцена не в рамці, а **на весь екран** — будинок сприймається більшим. Панель
пливе над нею на розмитому склі, тому не «ріже» композицію.

### Типографіка

| Роль | Шрифт | Розмір / вага |
|---|---|---|
| Заголовок кроку | **Inter** 500 | 19 px |
| Усі числа, розміри, ціна | **JetBrains Mono** 500 | 13–26 px, табулярні |
| Мікрозаголовки | JetBrains Mono 400 | 11 px, `letter-spacing .1em`, нижній регістр |
| Інтерфейс | Inter 400/500 | 14 px |

Моноширинний для чисел — не прикраса: `2400 мм`, `35°`, `RAL 7016` читаються
як специфікація, і колонки не «пливуть».

| Лінії | `rgba(255,255,255,.09)` | рамки |
| Текст | `#ECEFF2` | значення |
| Текст другорядний | `#8D959E` | підписи |

Будівельний помаранчевий на графіті — і впізнавано «про будівництво», і на

### Рух

| Що | Тривалість | Крива |
|---|---|---|
| Наведення | 180 мс | `cubic-bezier(.16,1,.3,1)` (пружна) |
| Натискання | 120 мс, масштаб 0.97 | там само |
| Зміна кроку (панель) | 260 мс, зсув 10 px справа | пружна |
| Підкреслення активного кроку | 260 мс, розтягується | пружна |
| Прогрес унизу | 260 мс, ширина | пружна |

Рух коротший, ніж у варіанта A, і трохи «пружинить» — так інтерфейс відчувається
чутливішим, як інструмент.

### Кому підходить

Клієнт, який хоче **крутити й міряти**. Темне тло вигідно подає будь-який
матеріал: і світлу штукатурку, і чорний фальц. Добре працює на великому екрані.

### Ризики

Темна тема складніша в друку й у презентації на проєкторі. Скляна панель
потребує уваги до продуктивності на слабких ноутбуках (blur + 3D).

## Моя рекомендація

**Взяти композицію B, а характер — A.** Тобто: сцена на весь екран і плаваюча
панель (це об'єктивно краще для конфігуратора — будинок більший, UI не ріже
екран), але у світлій темі, з теракотовим акцентом і спокійнішим рухом.

Причина: сцена в рамці (варіант A) красива, але з'їдає 15–20% площі будинку —
а будинок тут і є продукт. Решта переваг A (типографіка, повітря, спокій)
переноситься у плаваючу композицію без втрат.

Якщо ж хочеться саме «дорого й журнально» — A цілком самодостатній.

## Що вирішити далі

1. Який варіант беремо за основу — або гібрид, як у рекомендації?
2. Світла чи темна тема головна? (можна зробити перемикач, але одна має бути типовою)
3. Акцент: теракота `#C4552D` чи помаранчевий `#F97316`?
4. Кроки: погоджуємо реорганізацію 11 → 10?
5. Чи потрібен режим «своє» (малювати вручну) на кожному кроці — це впливає на
   складність панелі.

Після відповідей я доведу обраний варіант до повного макета всіх станів
(наведення, помилка, порожній стан, завантаження) і перенесу токени в
`METHOD-V3.md` як розділ 1.
