# CLAUDE.md

Гайд для роботи з цим репозиторієм. Українською — весь інтерфейс і комунікація українською.

## Що це

3D-конфігуратор будинку для будівельної компанії: клієнт крок за кроком збирає
будинок, бачить живу орієнтовну ціну (у майбутньому — лишає заявку).

**Стек:** React 19 · TypeScript · Vite · Three.js (react-three-fiber + drei) · zustand

## Команди

```bash
npm run dev        # локально → http://localhost:5173
npm run build      # продакшн у dist/
npx tsc -p tsconfig.app.json --noEmit   # перевірка типів (роби перед пушем)
```

## Структура

| Папка | Що там | Правило |
|---|---|---|
| `src/config/` | **Тільки дані**: кроки, форми, матриця доступності, ціни, типи | Більшість правок — тут |
| `src/locales/` | Усі тексти інтерфейсу (українська) | Жодного тексту в компонентах |
| `src/state/` | zustand-store: конфігурація, поточний крок, viewFloor, каскадне скидання | |
| `src/lib/` | Чисті функції: геометрія плану (`floorplan.ts`, `lshape.ts`), ціна (`price.ts`) | Без React і Three.js |
| `src/components/` | DOM-інтерфейс: панель, степер, поля кроків, ціна | |
| `src/scene/` | Усе всередині `<Canvas>`: світло, земля, `PlanView` (вид зверху) | |

Плани будинку: прямокутний/квадратний — з текстової сітки (`floorplan.ts`,
каталог у `config/layouts.ts`); **Г-подібний — параметричний** (`lshape.ts`).
`generateHousePlan(config)` диспетчеризує за `config.shape`.

## Правила анімації плану (PlanView.tsx) — ОБОВ'ЯЗКОВІ

Вид зверху анімує кольорові зони кімнат на плиті фундаменту. Правила, вироблені з
замовником (Lev), діють для БУДЬ-ЯКОЇ кімнати, теперішньої і майбутньої:

1. **Нічого не «перескакує».** Позицією та масштабом володіє ЛИШЕ `useFrame`
   (через `easing.damp3`). НЕ прив'язуй змінні значення до реактивних пропсів
   three.js (`position={[...]}`) — r3f миттєво застосовує зміну пропа й перебиває
   анімацію. Початкова позиція фіксується раз через `useState(() => ...)`.

2. **Стабільна ідентичність.** Кожна кімната має стабільний `id` за РОЛЛЮ
   (`bedroom-2`, `ensuite-bath`, `corridor-v`…), а не `тип#номер`. Задається в
   генераторі (`lshape.ts` через хелпер `rect(id, type, …)`; `floorplan.ts` —
   `id: ch`, символ сітки). `id` = ключ анімації (прибрана кімната зберігає
   ідентичність → плавно зникає, а не «морфить» у сусідню). НЕ повертайся до
   `тип#індекс` — це був корінь багів різкого зникнення й спільної підсвітки.

3. **Підсвітка = `group ?? id`.** Частини ОДНОГО приміщення мають спільний
   `group` (майстер, прихожа) → підсвічуються разом. Решта — унікальні → окремо.

4. **Секвенція (процеси не перетинаються):**
   - ДОДАВАННЯ: спершу росте фундамент + наявні кімнати стають на місце; нова
     кімната чекає `ENTER_DELAY`, тоді росте.
   - ВИДАЛЕННЯ: спершу зникає/зменшується кімната; фундамент стискається лише
     після `SLAB_SHRINK_DELAY`. Напрям = порівняння площі плити з попередньою.

5. **Тонкі інструменти проти колізій** (опційні поля `RoomZone`):
   - `anchorZ: 'min' | 'max'` — рости/зникати ВІД грані по Z, а не з центру
     (щоб не залазити на сусіда). Приклад: гардероб-смуга `anchorZ:'min'`.
   - `lazyStretch: true` — рости повільніше / стягуватись швидше, щоб відставати
     від сусіда, що рухається. Приклад: вертикальний коридор.

`src/scene/useEntrance.ts` — МЕРТВИЙ код, не використовується.

## Робочий процес

- Після правок: `tsc --noEmit` → коміт → `git push origin main`. Vercel
  деплоїть автоматично з `main` (GitHub-інтеграція, без `vercel.json`).
- Візуальну перевірку в браузері проводить замовник — НЕ запускай dev-сервер для
  скріншотів (3D-канвас усе одно не знімається через безперервний render-loop).
- Граф знань graphify (`graphify-out/`) — оновлювати під кінець фічі, не щоразу
  (код-екстракт AST безкоштовний). `graphify-out/` у `.gitignore`.
- Мінімальні точкові зміни: міняй лише те, що просять.
